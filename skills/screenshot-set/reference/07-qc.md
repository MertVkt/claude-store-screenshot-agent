# 07 · Quality control

Three layers: measurement (scripts), visual check (Claude looks at the contact sheet), a second opinion (optional).

## 1. Preview QC (`render.mjs`, on every render)

Scripts report levels as `ERROR`, `WARN` and `FITTED`.

| Level | Check | What to do |
|---|---|---|
| ERROR | font did not load, drawn with a fallback font | fix the `file` path or the internet connection; do not continue with the fallback font |
| ERROR | text exceeded `maxLines` (shrank down to `minSize` and still did not fit) | shorten the text |
| ERROR | two texts overlap | position or text |
| ERROR | text overflows the canvas or a panorama slice | `w`, `x` or text |
| ERROR | contrast with the background under the text is below the threshold (median; large text 3, small 4.5, WCAG 2.1) | change the color role, the background or the position; over a photo, put a dark/light `shape` behind it |
| WARN | part of the text sits in a low-contrast area (worst 10%) | it lands on a gradient/photo transition; move it or calm the background |
| WARN | text collides with the device or an image | intentional (badge over the device) or not |
| WARN | headline smaller than 0.06 × width | unreadable in search; enlarge or shorten |
| FITTED | text was shrunk (old → new px) | informational; written to `fit.json`, Figma uses the same |

The collision check uses the real line boxes, not the text box; a short line with space left on the right is not
counted as colliding with the object next to it.

## 2. Figma localization report (`texts` in the `localize` result)

For each text: line count, `maxLines`, size (before, after) and height increase. `ERROR: does not fit, shorten the text` is
not delivered. Figma's line count is height / line height; if the designer set line height to "Auto", about 1.2 is
assumed.

## 3. Delivery verification (`verify_shots.py`)

See [06-delivery](06-delivery.md). No delivery without exit code 0.

## 4. Visual checklist (looking at the contact sheet)

Read the contact sheet at a small size, as in the store:

- Do the first 3 images explain on their own what the app does? Are the headlines readable at that size?
- Is the series consistent: the same headline position rhythm, the same font, the same color family, devices at
  the same size?
- Are the device screens real and clean (9:41, no personal data, no empty-state screen)?
- Is the accent color readable (no dark accent on a dark background)?
- Each language: does the translation fit the headline, is the emphasis on the right word, are the line breaks
  natural?
- If it went to Figma: do the designer's changes show up in the export (not mixed up with an old preview)?

Give the user what you found as a list and suggest fixes; do not change an approved design in Figma on your own.

## 5. Second opinion (optional)

If a creative comparison against competitors is wanted, a vision-model reviewer can work on images too. Example
with `gemini-qc`, an optional tool that is not included in this plugin:

```bash
gemini-qc Work/final_en-US.png Work/ref_competitor.png -p "Compare these two App Store screenshot sets: the message of the first 3 images, readability, hierarchy, consistency. Give concrete suggestions."
```

The model does not measure, it comments; pixel, size and color numbers come from the scripts.
